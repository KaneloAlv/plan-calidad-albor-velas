1. Modelo de Calidad ISO/IEC 25010

El modelo seleccionado para este proyecto es ISO/IEC 25010 (SQuaRE), que define 8 características de calidad del producto. Se eligió por ser un estándar internacional enfocado específicamente en la evaluación de software, alineado con las necesidades críticas del negocio.

Justificación

  • Enfoque en producto: Evalúa el software en sí, no solo los procesos.
  • Alineación: Sus 8 características encajan con las necesidades de Albor Velas.
  • Medible: Permite definir métricas cuantitativas y pruebas trazables.
  • Respaldo: Estándar reconocido, compatible con otros marcos.

Características clave

  • Adecuación funcional – Cumple los requisitos del negocio.
  • Usabilidad – Interfaz intuitiva para el equipo.
  • Fiabilidad – Alta disponibilidad y tolerancia a fallos.
  • Seguridad – Protección de datos de clientes y transacciones.
  • Mantenibilidad – Código limpio y fácil de evolucionar.
  • Desempeño – Respuesta rápida en consultas.

Enfoque complementario

Si bien el modelo principal es ISO/IEC 25010, se toman buenas prácticas de CMMI Nivel 2 (Gestionado) para estructurar el seguimiento, control y planificación del proyecto.

2. Métricas de Calidad 6 métricas

Se definen 6 métricas cuantitativas alineadas con las características de ISO/IEC 25010, con metas específicas para garantizar la calidad del producto.

# Métrica ISO/IEC 25010 Forma de medición Meta
1 Tasa de defectos Fiabilidad (Defectos en prod / Total defectos) × 100 < 5% escapen a producción
2 Cobertura de pruebas Mantenibilidad / Fiabilidad % líneas/ramas ejecutadas por pruebas automatizadas ≥ 80% en módulos críticos
3 Tiempo de respuesta Eficiencia de desempeño ms en responder peticiones (JMeter, k6) < 2 segundos (p95)
4 Complejidad ciclomática Mantenibilidad N° de caminos independientes (SonarQube) ≤ 10 por función
5 Disponibilidad (uptime) Fiabilidad % tiempo operativo (UptimeRobot, Grafana) ≥ 99.5% mensual
6 Satisfacción del usuario Usabilidad Encuestas NPS / escala Likert ≥ 4/5

3. Plan de Pruebas 7 tipos + 10 casos

El plan de pruebas cubre todos los niveles necesarios para garantizar la calidad del sistema antes de su puesta en producción.

Tipos de pruebas

Unitarias

Validan funciones y componentes individuales.

Integración

Validan comunicación entre módulos.

Sistema

Validan el sistema completo end-to-end.

Aceptación (UAT)

Validan que el sistema cumple los requisitos del usuario final.

Carga / Rendimiento

Validan comportamiento bajo múltiples usuarios concurrentes.

Seguridad

Validan control de acceso y protección de datos.

Usabilidad

Validan que la interfaz sea intuitiva.

Casos de prueba

# Caso de prueba Entrada / Acción Resultado esperado
1Registro de cliente nuevoDatos válidosRegistro creado, confirmación mostrada
2Registro de pedido con productosSelección de productosPedido creado, inventario actualizado
3Actualización de estado de pedidoCambiar a "En producción"Estado actualizado, notificación al cliente
4Consulta de inventario en tiempo realBuscar "cera para velas"Cantidad exacta disponible
5Registro de pago parcialAbono $20.000 sobre $60.000Pago registrado, saldo actualizado
6Búsqueda de pedidosNombre "María" + estado "En producción"Pedidos filtrados correctamente
7Reporte de ventas mensualMes "Agosto 2026"Reporte con ingresos y productos top
8Login con credenciales inválidasUsuario/contraseña incorrectosAcceso denegado
9Notificación automáticaEstado → "Empacado"Notificación enviada al cliente
10Cancelación de pedidoPedido en "En producción"Estado "Cancelado", inventario restaurado

Criterios de aceptación

  • 100% de casos de prueba críticos deben pasar sin errores.
  • Cobertura de pruebas ≥ 80% en módulos críticos.
  • Cero defectos de severidad "crítica" o "alta" abiertos.
  • Tiempo de respuesta < 2 segundos bajo carga normal.
  • Validación y firma de conformidad por la propietaria de Albor Velas.
  • Funcional en Chrome, Firefox, Safari (mobile y desktop).

4. Gestión de la Configuración Gitflow + 3 entornos

Control de versiones

  • Herramienta: Git + GitHub/GitLab
  • Estrategia: Gitflow (main, develop, feature/*, release/*, hotfix/*)
  • Versionado: Semántico (MAJOR.MINOR.PATCH)
  • Commits: Convencionales (feat:, fix:, docs:, etc.)

Entornos diferenciados

  • Desarrollo: Local, integración continua
  • Pruebas/QA (staging): Replica producción, datos ficticios
  • Producción: Datos reales, acceso restringido

Control de cambios

  • Pull requests con code review obligatoria
  • CHANGELOG.md para registrar cambios
  • Vincular a tickets en Jira/Trello/GitHub Projects
  • Variables de entorno con .env (no versionado)

6. Soporte y Seguimiento Post-Entrega SLA definido

Mesa de ayuda

Canal de atención (correo y/o chat) para resolver dudas e incidencias, con SLA definido según criticidad.

Reporte de incidencias

Sistema de tickets (Freshdesk, Zendesk) para registrar errores o solicitudes, clasificados por prioridad.

Monitoreo continuo

Herramientas de observabilidad (logs, métricas) para detectar fallos proactivamente.

Mantenimiento

Correctivo: Corrección de defectos en producción.
Evolutivo: Mejoras y nuevas funcionalidades periódicas.

Encuestas de satisfacción

Revisiones periódicas con encuestas breves para retroalimentar el backlog de mejoras.

SLA

  • Crítica: < 4 horas
  • Alta: < 24 horas
  • Media: < 48 horas
  • Baja: < 1 semana

9. Roles del Equipo de Desarrollo 6 roles

Product Owner

Representa a Albor Velas y Detalles, gestiona el backlog, prioriza requisitos y asegura que el producto entregue valor al negocio.

Scrum Master

Facilita el proceso ágil, elimina impedimentos, asegura el cumplimiento de sprints y promueve las mejores prácticas.

Desarrollador Frontend

Implementa la interfaz de usuario responsive, asegurando una experiencia óptima en todos los dispositivos.

Desarrollador Backend

Implementa la API, lógica de negocio, base de datos e integraciones con servicios externos.

QA / Tester

Diseña y ejecuta casos de prueba, reporta defectos y garantiza la calidad del producto antes de cada entrega.

DevOps

Gestiona la infraestructura, despliegues continuos, monitoreo y asegura la disponibilidad del sistema.

Conclusiones Beneficios

Calidad asegurada

La aplicación del estándar ISO/IEC 25010 permite aterrizar la calidad en indicadores concretos y medibles, definiendo un plan de pruebas trazable y criterios de aceptación objetivos.

Control total

La gestión de configuración y el despliegue organizado (entornos separados, control de cambios) evitan sorpresas al lanzar a producción.

Soporte continuo

El soporte post-proyecto asegura que la calidad no termina con la entrega: el sistema evoluciona con el negocio.

Beneficios para Albor Velas

  • ✓ Eliminación de pérdida de información
  • ✓ Atención al cliente en segundos
  • ✓ Inventario actualizado en tiempo real
  • ✓ Decisiones estratégicas basadas en datos
  • ✓ Escalabilidad sostenible
